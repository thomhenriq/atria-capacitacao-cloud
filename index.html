Mão na massa

Passo a passo do deploy

Escolha o nome do seu bucket e a região — todos os comandos e a policy abaixo se atualizam sozinhos.

Pegue os arquivos do site

Clone o repositório ou baixe o ZIP: é exatamente o que vai pro bucket.

git clone https://github.com/thomhenriq/atria-capacitacao-cloud.git
Baixar ZIP Ver no GitHub
  1. 1

    Crie o bucket

    No Console da AWS, abra o S3 → Create bucket. Use o nome atria-cloud-seunome e a região sa-east-1. O resto pode ficar no padrão por enquanto.

  2. 2

    Libere o acesso público

    Aba Permissions → Block public access → Edit. Desmarque Block all public access, salve e digite confirm.

    Só faça isso em buckets feitos para conteúdo público. Dados sensíveis nunca vão num bucket aberto.

  3. 3

    Adicione a bucket policy

    Ainda em Permissions → Bucket policy → Edit. Cole a policy abaixo: ela permite que qualquer pessoa leia (s3:GetObject) os arquivos do bucket.

    bucket-policy.json 
    {
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "PublicReadGetObject",
      "Effect": "Allow",
      "Principal": "*",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::atria-cloud-seunome/*"
    }
  ]
}
  4. 4

    Ative o static website hosting

    Aba Properties → role até o fim → Static website hosting → Edit → Enable.

    • Index document: index.html
    • Error document: error.html
  5. 5

    Faça o upload dos arquivos

    Aba Objects → Upload. Arraste o index.html, o error.html e a pasta assets/. O index.html precisa ficar na raiz do bucket, não dentro de outra pasta.

    atria-cloud-seunome ├── index.html ├── error.html └── assets/ ├── styles.css · main.js └── favicon.svg · clouds-*.svg · logo
  6. 6

    Acesse o seu site

    Em Properties → Static website hosting, copie o Bucket website endpoint. Deve ser parecido com:

    http://atria-cloud-seunome.s3-website-sa-east-1.amazonaws.com

    Abriu e apareceu “Você está no ar!” no card lá do topo? Deploy concluído. 🎉
